## 🔧 Lo que se hizo

### 1. Manifiesto de paquetes por hook de pacman

| Archivo del vault | Instalado en | Qué hace |
|---|---|---|
| `assets/system/usr/local/bin/pkglist-dump` | `/usr/local/bin/pkglist-dump` | Como root, escribe `pacman -Qqen` y `pacman -Qqem` en `~/.config/pkglist/{pacman,aur}.txt` de **cada usuario que tenga ese directorio** (opt-in), con su dueño |
| `assets/system/etc/pacman.d/hooks/pkglist.hook` | `/etc/pacman.d/hooks/pkglist.hook` | `PostTransaction` en cada Install/Remove |

Lista actual: 230 paquetes de los repos y 12 de AUR. Los dos `.txt` se versionan en `sura-home` con dotbare (rama + PR, [sura-home#1](https://github.com/robert-flo/sura-home/pull/1)). `rebuild.sh` paso 15 instala ambos archivos.

### 2. `assets/restore.sh`

```bash
gh auth login                                   # humano, antes de nada
/zt/<vault>/assets/restore.sh --check           # qué haría
/zt/<vault>/assets/restore.sh                   # restaurar
/zt/<vault>/assets/rebuild.sh                   # después: reinstala y verifica el stack
```

| Paso | Qué hace |
|---|---|
| 0. Requisitos | Omarchy, git, gh, jq, rsync, `gh` autenticado (si no, termina), dotbare (yay) y bun (mise) |
| 1. `sura-home` | `dotbare finit -u` por HTTPS, refspec, `showUntrackedFiles no`, remoto a SSH; `chmod` de `~/.ssh` y `~/.gnupg`; reubicación |
| 2. Paquetes | Instala lo que falte de `pacman.txt` y `aur.txt` (`comm` contra lo instalado) |
| 3. `sura-brain` | Respalda un `~/.claude` existente en `.tgz` y hace `checkout -f -B master origin/master`; reubicación |
| 4. Árbol USER | Clona `sura-brain-user` (aparta un árbol previo); reubicación; reapunta el symlink `NIXFREDOS/USER` |
| 5. Conversaciones | Clona `sura-conversations`; copia `memory.db` y `projects/` si faltan |
| 6. Dependencias | `bun install --frozen-lockfile` en cada `bun.lock` versionado sin `node_modules` (menos `skills/nixfredOS/install/`) |
| 7. Portabilidad | Informa archivos versionados que aún contienen `/home/<otro usuario>/` |

| Opción | Uso |
|---|---|
| `--check` | Solo informa |
| `--no-push` | Banco de pruebas: el push URL de los cuatro repos queda en `no_push` |
| `--skip-packages` | Salta el paso 2 |
| `RESTORE_FROM_HOME=/home/x` | HOME de origen de los backups (por defecto `/home/gracie`) |

> [!IMPORTANT]
> **Por qué clona por HTTPS.** En una PC nueva todavía no hay llave SSH: viene dentro de `sura-home`. `restore.sh` inyecta `gh auth git-credential` como helper con `GIT_CONFIG_COUNT` (sin tocar `~/.gitconfig`) y, al terminar cada repo, cambia `origin` a SSH.

### 3. Banco de pruebas: usuario `melitta`

```bash
sudo useradd -m -s /bin/bash -c "Melitta" -G wheel,audio,input,video melitta
echo "melitta ALL=(ALL) NOPASSWD: ALL" | sudo tee /etc/sudoers.d/04_melitta && sudo chmod 440 /etc/sudoers.d/04_melitta
sudo loginctl enable-linger melitta            # systemd --user sin sesión gráfica

T=$(gh auth token)
sudo -u melitta env -i HOME=/home/melitta USER=melitta LOGNAME=melitta SHELL=/bin/bash TERM=xterm \
  PATH=/usr/local/bin:/usr/bin:/bin XDG_RUNTIME_DIR=/run/user/1003 \
  DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/1003/bus GH_TOKEN="$T" \
  bash -lc 'cd ~ && /zt/<vault>/assets/restore.sh --no-push'
# lo mismo con 'export PATH="$HOME/.local/share/mise/shims:$HOME/.local/bin:$PATH"; /zt/<vault>/assets/rebuild.sh'
```

Para volver a empezar desde cero: `sudo loginctl disable-linger melitta; sudo pkill -u melitta; sudo userdel -r melitta` y repetir. Para QA gráfica en SDDM/Hyprland: `sudo passwd melitta`.

> [!CAUTION]
> Melitta comparte la máquina con `gracie`: Tailscale (daemon de sistema), los puertos de Pulse (31337) e Interceptor (20220) y los hooks de pacman. Sus servicios de nixfredOS quedan habilitados por los symlinks restaurados y arrancarían en el próximo arranque (linger), compitiendo por esos puertos. Su `brain-backup` hace commits locales y registra `push failed` (esperado con `no_push`).

## ⚠️ Trampas encontradas

> [!WARNING]
> **1. Rutas absolutas `/home/gracie` en los archivos restaurados.** El primer intento en Melitta falló en el paso 1: el `~/.config/git/config` restaurado incluía `/home/gracie/.config/git/delta.gitconfig` y cada `git` posterior moría con `Permission denied`. Arreglos: la config de Git usa `~/` ([sura-home#2](https://github.com/robert-flo/sura-home/pull/2); Git expande `~/` en `include.path`, `excludesFile`, `attributesFile` y la llave de firma SSH), y `restore.sh` reescribe `/home/gracie` → `$HOME` en los archivos de texto versionados de los tres árboles (13 en `~`, 8 en `~/.claude`; unidades `com.nixfredos.*`, marcadores de GTK, `obsidian.json`, wrappers de Hermes…).

> [!WARNING]
> **2. La config global de Git restaurada dirige la restauración.** Aunque las rutas fueran correctas, un `~/.config/git/config` a medio restaurar puede romper el resto. `restore.sh` exporta `GIT_CONFIG_GLOBAL=/dev/null`.

> [!WARNING]
> **3. El token de `gh` no viaja en `sura-home`.** `~/.config/gh/hosts.yml` se restaura, pero el token vive en el keyring (`gnome-keyring`) de la PC de origen: `gh auth status` dice *"The token in default is invalid"*. `gh auth login` sigue siendo un paso humano (y `restore.sh` lo exige antes de empezar). El login de `cursor-agent` sí viaja (`~/.config/cursor/auth.json`).

> [!WARNING]
> **4. Tailscale es de todo el sistema.** `rebuild.sh` ejecutado por otro usuario de la misma PC cambió el operador de `gracie` a `melitta` (`tailscale set --operator`). Revertido, y el paso 13 ahora no toca un operador que ya pertenece a otro usuario.

> [!WARNING]
> **5. Timer habilitado pero detenido.** `sura-home` restaura el symlink de `timers.target.wants/brain-backup.timer`, así que el timer figura `enabled` pero no corre hasta el siguiente arranque. El paso 14 ahora exige `is-enabled` **y** `is-active`.

> [!WARNING]
> **6. Un `~/.claude` a medio restaurar.** Tras un fallo, `~/.cfg` y `~/.claude` quedan a medias y `restore.sh` se niega a pisar un `~/.cfg` que no apunta a `sura-home`. En el banco de pruebas lo más limpio es recrear el usuario.
