## 🔧 Lo que se hizo

1. **Context7 en `~/.cursor/mcp.json`** como servidor HTTP remoto (sin instalar nada y sin clave; con límite de uso gratuito). Tiene dos herramientas: `resolve-library-id` y `query-docs`.
2. **Aprobación:** `cursor-agent mcp list` lo mostraba como "needs approval". Se aprobó con `cursor-agent mcp enable context7`.
3. **Regla** "Current docs via Context7" en `OPERATIONAL_RULES.md`:
   - para librerías cuya API cambia entre versiones, Sura consulta Context7 antes de escribir código o explicar cómo se hace algo, usando la versión del lockfile cuando la hay;
   - dice de qué documentación sale la respuesta, o avisa que responde de memoria;
   - a Upstash solo se le mandan nombres de librerías y preguntas genéricas, nunca código de clientes, nombres privados ni secretos;
   - lo estable (POSIX, bash, git básico) no lo necesita.
4. **Canario `context7`.**
5. **`rebuild.sh` paso 22:** comprueba la entrada en `mcp.json` (que llega con `sura-home`) y aprueba el servidor si hace falta.

## ⚠️ Trampas encontradas

> [!WARNING]
> **1. Instalar el MCP no hace que se use.** Sin la regla, Sura respondió la pregunta de Astro 5 de memoria, sin llamar a ninguna herramienta. Con la regla, lo consultó las dos veces.

> [!WARNING]
> **2. Un MCP nuevo arranca sin aprobar.** Hasta ejecutar `cursor-agent mcp enable` no se carga. En una PC nueva lo hace el paso 22.

> [!WARNING]
> **3. Context7 sirve la documentación más reciente.** Para Astro devolvió la de la versión 6. Sura lo dijo y ajustó el ejemplo a la 5, pero en un proyecto real hay que mirar el lockfile.
