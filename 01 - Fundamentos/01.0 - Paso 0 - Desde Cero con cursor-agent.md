## 🎯 Objetivo

El capítulo original lo hace el humano a mano, porque todavía no hay IA. Aquí el humano ya tiene un agente desde el inicio, así que el agente ejecuta y explica, y el humano aprueba. Al terminar: `cursor-agent` arranca sin errores en el modo de permisos elegido.

## 🔧 Pasos

### 1. Instalar el harness — ✅

Original: `curl -fsSL https://claude.ai/install.sh | bash`. Aquí `cursor-agent` ya estaba instalado con `mise`:

```bash
command -v cursor-agent    # ~/.local/share/mise/installs/cursor-agent/latest/bin/cursor-agent
cursor-agent --version     # 2026.10.01-e373342
cursor-agent update        # para actualizar
```

### 2. El costo — ✅

El original recomienda el plan de Claude de $100–200/mes. Aquí cuenta el plan de Cursor: **Pro ($20/mes), pagado por un año por adelantado**. Cursor ha cambiado sus precios desde entonces; las condiciones vigentes son las de la cuenta.

> [!TIP]
> El equivalente del "te vas a quedar sin cuota" del original es el uso del plan de Cursor. El [[assets/upstream-site/how.nixfred.com/18-models|Capítulo 18]] trata cómo repartir el trabajo entre modelos.

### 3. Login — ✅

```bash
cursor-agent login       # abre el navegador (NO_OPEN_BROWSER=1 para no abrirlo)
cursor-agent status      # ✓ Logged in as 25asab015@ujmd.edu.sv
```

### 4. Modo de permisos — ✅ `--force`

| Original (Claude Code) | cursor-agent | Qué hace |
|---|---|---|
| `claude` (modo auto) | `cursor-agent --auto-review` | Un clasificador ejecuta solo lo seguro y pregunta el resto. |
| `claude --dangerously-skip-permissions` | `cursor-agent --force` (`--yolo`) | Ejecuta todo salvo lo denegado explícitamente. Lo que usa Fred. |
| Modo manual | `cursor-agent` | Pregunta antes de cada acción (según `~/.config/cursor/cli-config.json`). |

**Decisión:** `--force` desde el principio, igual que Fred.

> [!WARNING]
> Con `--force` el agente no pide permiso. La red de seguridad son los backups: el repo privado del [[assets/upstream-site/how.nixfred.com/07-forever-repo|Capítulo 7]] y el `brain` privado de nixfredOS. Hasta tenerlos, los cambios importantes siguen pasando por ramas y PR. La alternativa con barreras está en el [[assets/upstream-site/how.nixfred.com/19-permissions|Capítulo 19]] (`~/.config/cursor/cli-config.json`).

### 5. Shell: nixbash como capa sobre Omarchy — ✅

Original: `curl -sL https://raw.githubusercontent.com/nixfred/nixbash/main/install.sh | bash`.

**Qué es nixbash:** un entorno bash para **servidores Linux recién instalados**: banner con IPs, Tailscale, Docker e intentos de SSH; alias de paquetes (`si`, `aa`), red y monitoreo; funciones como `extract`, `mkcd`, `listening`, `push`/`pull`. No es solo para contenedores, pero su diseño es de servidor.

**Problema en Omarchy** (revisado en el fork el 2026-10-12):
- `install.sh` tenía fijo `NIXBASH_REPO=.../nixfred/nixbash/main`: ignoraba el fork.
- **Reemplazaba `~/.bashrc`**, que en Omarchy carga `env-bootstrap`, `default/bash/rc` y tu bloque propio (por ejemplo `try` con `TRY_PATH=/zt`).
- Cargado encima de Omarchy, pisaría `c` (opencode), `h` (herdr), `ff` (fzf), `ls`/`lt` (eza), cambiaría `cat`→`bat` y `vi`→`nano`, reemplazaría el prompt de starship, bajaría `HISTSIZE` de 32768 a 10000 y mostraría el banner en cada terminal.

**Solución:** [PJ-LARRY-fo-nixbash#1](https://github.com/robert-flo/PJ-LARRY-fo-nixbash/pull/1) (fusionado en `personal`, commit `0f6ab2f`). Combina nixbash con el diseño de Omarchy:

| Cambio | Detalle |
|---|---|
| Modo capa | Si `~/.bashrc` carga `default/bash/rc` de Omarchy, `install.sh` instala nixbash en `~/.local/share/nixbash/bashrc` y añade **una** línea `source` al final de `~/.bashrc` (idempotente). Sigue haciendo backup. |
| Omarchy manda | En modo capa, nixbash no toca prompt, historial, completados, `zoxide`/`fzf` ni los alias de Omarchy (`ls`, `lt`, `c`, `h`, `ff`, `cd`), ni `cat`/`vi`. |
| Banner | Desactivado en modo capa; se activa con `export NIXBASH_BANNER=1` en `~/.bashrc_local`. |
| Fuente | `NIXBASH_REPO` es configurable y por defecto apunta a `PJ-LARRY-fo-nixbash@personal`. `NIXBASH_REPLACE=1` fuerza el comportamiento original. |

Instalación (como tu usuario):

```bash
curl -sL https://raw.githubusercontent.com/robert-flo/PJ-LARRY-fo-nixbash/personal/install.sh | bash && source ~/.bashrc
```

Resultado real:
- Backup: `~/.bashrc.pre-nixbash.20261012-210232`.
- Paquetes nuevos (pacman, vía sudo sin contraseña): `tree`, `htop`, `ncdu`. El resto ya estaba (`bat`, `fzf`, `rg`, `btop`, `fastfetch`, `eza`, `zoxide`).
- Final de `~/.bashrc`:
  ```bash
  # NixBash: server aliases and functions layered over Omarchy (Omarchy keeps prompt, history and its aliases)
  [[ -r "${XDG_DATA_HOME:-$HOME/.local/share}/nixbash/bashrc" ]] && source "${XDG_DATA_HOME:-$HOME/.local/share}/nixbash/bashrc"
  ```

> [!NOTE]
> El clon de trabajo del fork está en `~/Projects/nixbash` (`origin` = fork, `upstream` = nixfred con push deshabilitado), como pide el sitio para todo lo que se trae al stack.

Desinstalar la capa: borrar la línea `nixbash/bashrc` de `~/.bashrc` y `rm -r ~/.local/share/nixbash`.

### 6. Reiniciar y continuar la conversación — ✅

```bash
cursor-agent --force --continue   # o: cursor-agent resume / cursor-agent ls
```

Verificación no interactiva desde el vault:

```bash
cursor-agent -p --force --trust "Responde solo con la palabra: listo"   # → listo (exit 0)
```

### 8. Cuando algo falla: la IA arregla la IA

Pegar el error en `cursor-agent` y decir "arréglalo"; abrir una segunda sesión para destrabar la primera; o pedirle que lea este vault y compare con la máquina. Repetir hasta que arranque sin errores.
