## 🎯 Idea central

**El entorno alrededor del modelo (el *harness*) importa tanto como el modelo.** Por eso casi todo el resto del playbook es configuración, no elegir modelos. El original lo cuenta desde Claude Code; aquí aplica igual a `cursor-agent`.

---

## 🧠 Las seis ideas, traducidas a cursor-agent

| # | Idea del original | Qué significa aquí |
|---|---|---|
| 1.1 | **La terminal fue un accidente.** Claude Code nació al *eliminar* el editor (el prototipo "Clyde") y poner el modelo en la terminal. | `cursor-agent` es lo mismo del lado de Cursor: el agente sin el IDE. El IDE sigue existiendo, pero el centro de gravedad de este playbook es la terminal. |
| 1.2 | **Una CLI gana a un IDE**: archivos reales, máquina real, y un entorno al que vuelves siempre, así que la configuración se acumula. | Lo que se acumula aquí: `AGENTS.md`, rules, skills, hooks, MCP y este vault. Cada capítulo añade una pieza y ninguna se pierde. |
| 1.3 | **El modelo ya sabe Bash.** Pocas herramientas, con permisos aplicados con firmeza. | El agente usa la shell para casi todo. Los permisos viven en `~/.config/cursor/cli-config.json` (`permissions.allow/deny`), no en herramientas especiales. |
| 1.4 | **Diseño de doble uso**: humano y agente comparten la misma superficie (`!` para shell, los mismos slash commands y skills). | Las skills y comandos que escribas los puedes invocar tú y el agente. Construir todo así: si sirve para ti, sirve para él. |
| 1.5 | **El harness multiplica al modelo.** El mismo modelo rinde muy distinto según el entorno; si cambias el modelo, el harness es lo que sigue siendo "tu IA". | Con `cursor-agent` el modelo es intercambiable (`--model`, hoy `Auto`). La identidad está en el harness: nixfredOS, la memoria y este vault. |
| 1.6 | **Construye para ti y vive en el futuro.** Resuelve tu propia fricción, hazlo modificable, codifica lo que funcione. | Es lo que ya pasó en el Paso 0: nixbash chocaba con Omarchy, se arregló en el fork y se documentó. Ese ciclo es el método (Capítulo 20). |

> [!TIP]
> Para notar la diferencia entre modelos hay que darles una tarea difícil. En tareas fáciles todos parecen iguales.

## 📸 Línea base del harness (2026-10-12)

La foto de lo que había antes de construir nada. Los siguientes capítulos se comparan contra esta tabla.

| Pieza | Estado | Dónde |
|---|---|---|
| Configuración del CLI | `approvalMode: unrestricted`, sandbox desactivado, `allow: [Shell(ls)]`, modelo `Auto`, sin `statusLine` | `~/.config/cursor/cli-config.json` |
| Rules globales | ninguna | `~/.cursor/rules` no existe |
| Hooks | ninguno | `~/.cursor/hooks.json` no existe |
| MCP | ninguno | `~/.cursor/mcp.json` no existe |
| Skills propias | ninguna | `~/.cursor/skills` no existe |
| Skills de Cursor | 23 incluidas (`create-rule`, `create-hook`, `create-skill`, `statusline`, `update-cli-config`, `review`…) | `~/.cursor/skills-cursor/` |
| Subagentes | ninguno | `~/.cursor/agents/` vacío |
| Skills de Claude | `diagnose-crash`, `omarchy` | `~/.claude/skills/` |
| Contexto global | sin `AGENTS.md` en `~` | — |
| Shell | Omarchy + nixbash como capa | [[01.0 - Paso 0 - Desde Cero con cursor-agent\|Paso 0]] |

> [!NOTE]
> La configuración del CLI está en `~/.config/cursor/cli-config.json` (no en `~/.cursor/`). Corregido en [[10.1 - Equivalencias Claude Code a cursor-agent|10.1]].
