## 🎯 Objetivo

Una primera sesión que se gana la confianza: el agente **mapea el proyecto** para no hacer repetir las cosas, **muestra lo que consume** para que no haya sorpresas y **nunca finge**.

---

## 1. El mapa del proyecto (`/init`) — ✅

**Original:** `/init` escanea el proyecto y escribe un `CLAUDE.md` que se carga en cada sesión.

**En cursor-agent 2026.10.01 no existe `/init`** (revisada la lista de comandos del binario). El equivalente es un `AGENTS.md` en la raíz del proyecto, que `cursor-agent` carga solo (también lee `.cursor/rules/`, y `/rule` las gestiona). En este vault el mapa ya existe: `AGENTS.md`, escrito al crear el repo.

Verificación de que se carga sin pedírselo:

```bash
cd /zt/2026-10-12-robert-flo-PJ-LARRY-rf-playbook
cursor-agent -p --force --trust "Sin ejecutar herramientas ni leer archivos nuevos: según las reglas que ya tienes cargadas de este proyecto, responde: 1) rama por defecto, 2) nivel del humano, 3) desde qué repos se instala todo. Si no las tienes, di NO CARGADO."
```
```text
1) La rama por defecto es `master`, nunca `main`.
2) El humano tiene nivel avanzado en la terminal.
3) Todo se instala desde los forks `robert-flo/PJ-LARRY-fo-*`, en la rama `personal`.
```

> [!TIP]
> En un proyecto nuevo, el equivalente de `/init` es pedirle al agente: *"Lee este repo y escribe un `AGENTS.md` con la arquitectura, convenciones y archivos clave"*. Después se revisa con ojo crítico, como un PR de alguien recién llegado: casi todo bien, alguna cosa equivocada con total seguridad.

**Revisión crítica del `AGENTS.md` del vault:** se actualizó la sección de trailers, porque ahora `cursor-agent` ya no los añade (ver punto 3) y el push va por SSH.

## 2. La barra de estado (`/statusline`) — ✅

**Original:** `/statusline` con modelo, % de contexto, costo y rama. Sirve para que el humano no tenga dudas de cuánto gasta ni de lo cerca que está el agente de quedarse sin contexto.

**En cursor-agent** se configura `statusLine` en el archivo de configuración del CLI. Cada vez que cambia la conversación, ejecuta un comando que recibe un JSON por stdin (especificación en `~/.cursor/skills-cursor/statusline/SKILL.md`).

> [!IMPORTANT]
> **Dónde está la configuración:** el CLI usa `$XDG_CONFIG_HOME/cursor/cli-config.json` si `XDG_CONFIG_HOME` está definido, y `~/.cursor/cli-config.json` si no (comprobado en el código del CLI). Aquí está definido, así que es `~/.config/cursor/cli-config.json`. La skill de Cursor solo menciona `~/.cursor/`.

Script: `~/.config/cursor/statusline.sh` (copia versionada en `assets/home/.config/cursor/statusline.sh`). Muestra modelo y parámetros, barra de contexto (verde < 50 %, amarillo < 80 %, rojo ≥ 80 %), carpeta, rama de git con `*` si hay cambios sin commit, y worktree:

```text
Claude Opus (Thinking)  ▓▓▓▓▓▓░░░░ 63%  /zt/2026-10-12-robert-flo-PJ-LARRY-rf-playbook  ⎇ master
GPT-5  ▓▓▓▓▓▓▓▓▓░ 91%  ~/Projects/nixbash  ⎇ personal  wt:feat-x
```

> [!NOTE]
> **Ampliaciones posteriores.** La barra se adapta a `render_width_chars` (una línea si cabe; si no, sesión y uso en líneas separadas) y añade el uso de Cursor (gasto en 5 h, % del mes, ritmo, fin de ciclo) desde una caché que refresca `statusline-usage.sh` en segundo plano. En el [[02.5 - Capitulo 5 - nixfredOS en cursor-agent|Capítulo 5]] se sumó un segmento de nixfredOS (`statusline-nixfredos.sh`). Los tres scripts están en `assets/home/.config/cursor/`.

Configuración añadida (fragmento en `assets/home/.config/cursor/cli-config.fragment.json`, respaldo previo en `cli-config.json.bak-<fecha>`):

```json
"statusLine": {
  "type": "command",
  "command": "~/.config/cursor/statusline.sh",
  "padding": 0,
  "timeoutMs": 1500
}
```

> [!WARNING]
> **Sin costo en la barra, y es a propósito.** El JSON que recibe la barra no trae costo ni uso del plan, así que no se inventa. El uso del plan se consulta con `/usage`, y el desglose del contexto con `/context`.

> [!NOTE]
> **Fallo encontrado y corregido:** con `IFS=$'\t'`, `read` junta tabuladores consecutivos y un campo vacío (por ejemplo, sin `param_summary`) desplazaba el resto. El script separa los campos con `\x1f`.

## 3. Atribución de commits y PRs — ✅

En el código del CLI aparecen `attribution.attributeCommitsToAgent` y `attribution.attributePRsToAgent`, **activadas por defecto**. Son las que añaden `Co-authored-by` a los commits y la firma del agente a los PRs, lo que va contra la regla de no añadir coautores. Se desactivaron en la configuración (también se puede hacer con `/config`):

```json
"attribution": {
  "attributeCommitsToAgent": false,
  "attributePRsToAgent": false
}
```

> [!NOTE]
> Esto afecta a `cursor-agent`. El agente del IDE de Cursor tiene su propio ajuste; mientras tanto, la corrección con `git commit-tree` de `AGENTS.md` sigue siendo válida.

## 4. Leer la pantalla — ✅

Comandos de `cursor-agent` 2026.10.01 que cumplen el papel de `?`, `Ctrl+O` y `/release-notes` del original (lista sacada del binario):

| Para qué | Comando |
|---|---|
| Ayuda | `/help`, `/help <comando>` |
| Shell en línea; el agente ve la salida (doble uso) | `!` en una línea vacía, o `/shell` |
| Cuánto contexto queda | `/context`; resumir con `/summarize` |
| Uso del plan | `/usage` |
| Revisar cambios (conversación, staged, commits) | `/changes` |
| Volver a un mensaje anterior | `/rewind` |
| Pregunta aparte sin ensuciar el chat | `/btw` |
| Retomar o bifurcar chats | `/resume`, `/fork`, `/rename` |
| Modelo y modos | `/model`, `/plan`, `/ask`, `/auto-review`, `/max-mode` |
| Configuración interactiva | `/config` |
| Actualizar | `/update` · versión con `/about` |

Y lo más importante para un humano nuevo: **puede simplemente hablarle al agente.** Si se queda en blanco, el agente le ofrece opciones (Capítulo 3).

## 5. Voz y honestidad — ✅

El original habla de `/voice` en Claude Code y advierte que la voz *de salida* es un truco que cansa en una semana. **`cursor-agent` 2026.10.01 no tiene comando de voz**: no aparece en la lista del binario, y no se finge que sí. El dictado (voz → texto en cualquier app) es un módulo aparte: [[assets/upstream-site/how.nixfred.com/voice-dictation|Voice Dictation]].

**Ley desde el día uno:** honestidad antes que magia. Decir qué no se puede hacer, aunque luzca menos.

## 6. La vara de "sin experiencia nueva"

Todo lo que se construya (comandos, hooks, skills) debe funcionar al soltarlo, con nombres que digan lo que hacen y sin manual. Un asistente que solo sabe manejar quien lo creó es frágil.
